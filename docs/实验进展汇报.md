目前已经完成了从“单场景跑通”到“多场景实验闭环”的主要代码和实验工作，主线如下：

```text

-> 3 组采样预算实验
```

当前可以明确得到以下结论：

1. Building-aware Simplified LANC 已经能够在 FARM scene 11 上完成训练，并能迁移到 scene 12、scene 13 完成零样本预测。
2. 使用少量目标场景 UAV 模拟测点微调后，目标场景覆盖图误差确实下降，主动采样闭环成立。
3. `proposed_v2_j` 在 scene 12 的开发实验中表现最好，并明显优于旧版 `proposed`、`uniform_grid`、`weak_only` 等策略。
4. 在 scene 13 的多种子平均结果中，`proposed_v2_j` 的 RMSE 仍略高于随机采样，没有做到“全面超过所有 baseline”。
5. `proposed_v2_j` 的标准差更低，说明稳定性较好；在高采样预算下，它可以超过随机采样；在低采样预算下略输给随机采样。
6. 代码和精选结果已经上传 GitHub，适合直接作为阶段性汇报材料，但还不是完整真实无人机实验或最终论文终稿。

最需要如实汇报的一句话是：

> 当前实验已经证明“跨场景零样本预测 -> 主动采样 -> 微调提升覆盖预测”这条主线可行，但主动策略相对随机采样的优势还不够稳定，尚不能宣称全面领先。

## 2. 项目目标与实验假设

### 2.1 研究目标

原版 LANC 主要面向蜂窝网络覆盖预测。当前工作将它简化为适合 FARM 三维无线地图数据的版本，保留“解耦建模”的核心思想，但删除了 FARM 数据无法提供的 AAU、机械下倾、数字下倾、带宽和多 beam 等信息。

当前模型采用四分支结构：

```text
几何传播特征 -> 几何分支
频率特征     -> 频率分支
天线特征     -> 天线分支
建筑环境特征 -> 建筑分支
四个分支标量输出相加，再结合全局偏置得到覆盖预测
```

这里的“解耦”不是简单增加网络层数，而是让不同物理因素通过独立分支进入模型，减少不同类型特征之间的相互干扰。

### 2.2 输入和输出

模型输入包括：

- Tx 和 Rx 的三维相对位置。
- 距离、对数距离、垂直角、水平角。
- 频率。
- yaw、天线方向图编号和相对水平角。
- 接收点附近建筑密度、局部建筑高度、净空高度和路径遮挡比例。

模型输出包括：

- 点级 `signal_norm` 预测。
- FARM 编码尺度下的点级预测值。
- 三维覆盖图预测结果。
- 三维覆盖图真值和绝对误差图。
- NMSE、RMSE、PSNR、SSIM 和 mean error。

### 2.3 标签尺度说明

当前使用 FARM 的 `uint8` 标签，并归一化到 `[0, 1]` 后训练。

```text
signal_norm = FARM encoded value / 255
```

由于 FARM 原论文和当前数据文件中没有确认完整、可验证的 dB 解码公式，当前结果统一写成：

```text
encoded value
signal_norm
```

没有强行写成 dBm。这会带来两个影响：

- 可以比较不同模型在同一数据尺度上的相对误差。
- 暂时不能把误差直接解释成真实物理信号误差，例如“平均误差多少 dB”。

后续如果确认 FARM 官方解码方式，应统一回算编码值或真实信号强度，再重新生成论文表格。

## 4. 阶段一：FARM 适配版 LANC

对应提交：

```text
8d5523f  Implement FARM-adapted LANC experiment
```

### 4.1 本阶段目标

把原来的“仿真 Teacher 版 LANC”改造成可以读取 FARM scene 11 `.npy` 数据的点级预测模型。

主要输入：

```text
11/tx_positions_512.csv
11/11/freq35/pattern_120/*.npy
```

主要输出：

```text
runs/farm_lanc_v2_scene11_<timestamp>/
```

### 4.2 主要改动

1. 新增 `lanc/farm_data.py`，读取 FARM `.npy` 和 Tx 位置文件。
2. `.npy` 原始尺寸为 `(1, 30, 512, 512)`。
3. 水平网格默认使用 `stride=16`，把 `512 x 512` 降采样为 `32 x 32`。
4. 使用高度 `100/110/120/130m`。
5. 将每个 Tx、Yaw、Rx 和高度组合展开为点级样本。
6. 过滤 `value == 0` 的建筑占据点。
7. 按 `tx_id` 划分训练、验证和测试，避免同一个 Tx 同时进入不同集合。
8. 新增四分支 Building-aware LANC。
9. 增加点级指标、三维覆盖图、二维高度切片图和训练曲线。

### 4.3 遇到的难题

#### 难题 1：原版 LANC 的特征与 FARM 不匹配

原版模型假设能够获得 AAU、机械下倾、数字下倾、beam、带宽等蜂窝网络参数，但 FARM 当前使用的主要是频率、天线方向图、Tx/Rx 几何位置和建筑环境。

解决办法：

- 删除 FARM 无法提供的特征。
- 保留距离、角度、频率和天线方向。
- 新增 `frequency_ghz`、`antenna_pattern_id`、`yaw` 等 FARM 可提供特征。
- 将原论文的复杂多输出预测简化为一个标量信号强度预测。

#### 难题 2：原始体数据太大

`(1, 30, 512, 512)` 的体数据直接全分辨率训练会产生很大的内存和显存压力，GTX 1650 SUPER 不适合直接做高密度全量训练。

解决办法：

- 默认 `stride=16`。
- 先做空间降采样，再构造点级样本。
- batch size 设为 2048 或 4096。
- 保留完整地图用于评估，训练时只使用采样后的点。

#### 难题 3：建筑信息如何进入模型

FARM 数据没有直接给出统一的建筑轮廓特征，但 `.npy` 中 `value == 0` 可以近似表示建筑占据位置。

解决办法：

- 从 `value == 0` 取近似建筑高度图。
- 生成局部建筑密度。
- 生成局部建筑高度。
- 生成高度净空。
- 生成 Tx/Rx 路径上的简单建筑遮挡比例。
- 过滤位于建筑内部的接收点。

需要注意：这是近似建筑特征，不是标准 LiDAR 或 OSM 三维建筑物地图。

#### 难题 4：标签无法直接解释为 dBm

FARM 标签是 `uint8` 编码值。没有确认解码公式时，直接写成 dBm 会产生错误物理含义。

解决办法：

- 标签归一化为 `signal_norm`。
- 训练和评估同时记录 normalized scale 和 encoded scale。
- 在 README、manifest 和汇报中明确写出“不等于 dBm”。

#### 难题 5：训练集和测试集可能发生同 Tx 泄漏

如果随机拆点，同一个 Tx 的数据可能同时进入训练和测试，造成过高估计泛化能力。

解决办法：

- 按 `tx_id` 划分。
- scene 11 默认：

```text
train tx_id = 0-79
val tx_id   = 80-89
test tx_id  = 90-99
```

#### 难题 6：只预测数字不够直观

仅输出 MAE 和 RMSE 很难判断模型是否真正学到了空间覆盖结构。

解决办法：

- 输出三维预测图。
- 输出三维真值图。
- 输出三维绝对误差图。
- 输出每个高度层的二维切片。
- 输出 NMSE、RMSE、PSNR、SSIM 和 mean error。

## 5. 阶段二：Scene 12 主动采样闭环

对应提交：

```text
a64be0f  Add scene 12 active sampling experiment
```

### 5.1 本阶段目标

用 scene 11 训练好的模型预测新场景 scene 12，并模拟无人机只采集少量关键测点，再通过微调提高 scene 12 的预测精度。

实验主线：

```text
加载 scene 11 预训练模型
-> 隐藏 scene 12 标签
-> scene 12 零样本预测
-> 主动选择少量 rx_id
-> 从 FARM 真值揭示被选测点标签
-> 使用累计测点微调
-> 在未采样区域重新评估
```

### 5.2 为什么采样单位是 `rx_id`

一个 `rx_id` 表示一个三维无人机空间测点：

```text
(rx_row, rx_col, rx_height_m)
```

选中一个 `rx_id` 后，揭示该点下所有 Tx 和 Yaw 配置的标签，用于模拟无人机在同一位置完成多小区、多朝向测量。

评估时只在未采样的 `rx_id` 上计算指标，避免“测过的位置当然预测得准”导致误差虚低。

### 5.3 遇到的难题

#### 难题 1：新场景没有标签

scene 12 是目标场景，模型训练时不能直接看到它的标签。

解决办法：

- 先把 scene 12 当成未知场景进行零样本预测。
- 只向采样策略暴露预测图和建筑特征。
- 被策略选中的测点才从 FARM 真值中揭示标签。

#### 难题 2：覆盖图整体低估

V1 在跨场景预测时存在整体低估。mean error 为负，说明预测覆盖图整体偏暗或偏弱。

解决办法：

不增加第五个分支，也不做残差后处理，而是将模型升级为 `BuildingAwareLANCV2`：

- 几何分支加入 Tx/Rx 坐标。
- 几何分支加入 Tx 高度。
- 天线分支加入 `yaw_sin` 和 `yaw_cos`。
- 继续保留几何、频率、天线、建筑四个分支。

这样可以让模型直接学习 Tx 位置和朝向带来的系统性偏差。

#### 难题 3：目标域特征分布与源场景不同

scene 11 和 scene 12 的场景布局、Tx 位置和建筑分布不同。

解决办法：

- 源场景 scaler 和目标场景 scaler 分开拟合。
- 使用源模型权重初始化目标场景模型。
- 只使用目标场景已揭示标签做低学习率微调。

#### 难题 4：如何证明微调有效

只比较微调前后的训练误差没有意义，因为模型可能记住已测点。

解决办法：

- 每轮都只在未采样区域评估。
- 记录 zero-shot、每轮采样后和最终策略指标。
- 同时保存预测图、真值图和误差图。

### 5.4 阶段结果

scene 12 的代表性结果位于：

阶段判断：

- scene 11 模型可以直接迁移到 scene 12。
- 少量 UAV 模拟测点微调能够降低目标场景误差。
- 主动采样闭环在 scene 12 上成立。

## 6. 阶段三：增加 Baseline 并优化主动策略

对应提交：

```text
e1e4e1a  Add active sampling baselines and proposed v2 strategy
```

### 6.1 本阶段目标

原来的 `proposed` 策略没有稳定超过随机采样。本阶段增加中间 baseline，并设计 `proposed_v2` 系列，目标是让主动策略至少优于随机采样、弱覆盖优先和均匀网格。

### 6.2 当前策略定义

| 策略 | 选择依据 | 作用 |
| --- | --- | --- |
| `random` | 均匀随机选择未采样点 | 最基础随机 baseline |
| `uniform_grid` | 逐步最大化空间分散 | 模拟固定网格巡航 |
| `weak_only` | 选择预测信号最弱的点 | 只关注弱覆盖 |
| `building_only` | 选择建筑密度和遮挡最高的点 | 只关注建筑复杂区域 |
| `proposed` | 旧版弱覆盖 + 建筑 + 分散 | 旧策略消融 |
| `proposed_v2_a/b/c` | 弱覆盖、建筑、分散、梯度的不同权重 | 权重搜索 |
| `proposed_v2_j` | 先锁定建筑复杂度前 20%，再按建筑、分散、梯度排序 | 最终主线策略 |

`proposed_v2` 使用的四项分数为：

```text
weak_score      = 预测信号越弱，分数越高
building_score  = 建筑复杂度和路径遮挡越高，分数越高
diversity_score = 离已采样点越远，分数越高
gradient_score  = 覆盖图变化越剧烈，分数越高
```

`proposed_v2_j` 的实际逻辑是：

```text
先从建筑复杂度前 20% 的候选中筛选
再按照 0.70 building + 0.25 diversity + 0.05 gradient 排序
同时排除已经采样过的 rx_id
```

它不是简单选择最弱位置，而是将重点放在建筑复杂区域，再用空间分散和覆盖突变进行约束。

### 6.3 遇到的难题

#### 难题 1：弱覆盖优先会扎堆

只选择预测最弱的点，采样点可能集中在少量相似区域，无法代表整个目标场景。

解决办法：

- 增加 `diversity_score`。
- 每次选择后更新与已采样点的最小空间距离。

#### 难题 2：建筑复杂度和空间覆盖互相冲突

建筑最复杂的区域不一定包含最大的覆盖变化，而覆盖变化最大的区域也不一定建筑最复杂。

解决办法：

- 增加 `gradient_score`。
- 对建筑、弱覆盖、分散和梯度做不同权重组合。
- 禁止重复选择已采样点。

#### 难题 3：策略名称增多后难以统一比较

如果不同实验使用不同策略列表，最终无法直接比较。

解决办法：

- 统一策略名。
- 每轮写出 `active_round_metrics.csv`。
- 输出 `strategy_comparison_summary.csv`。

### 6.4 阶段结果

在 scene 12 的正式开发实验中，`proposed_v2_j` 最终表现最好：

| 策略 | Encoded RMSE | PSNR | SSIM |
| --- | ---: | ---: | ---: |
| `proposed_v2_j` | 4.5276 | 35.0134 dB | 0.9760 |
| `building_only` | 4.7043 | 34.6810 dB | 0.9745 |
| `uniform_grid` | 4.7810 | 34.5404 dB | 0.9777 |
| `random` | 4.7845 | 34.5341 dB | 0.9779 |
| `proposed` | 5.0413 | 34.0799 dB | 0.9799 |
| `weak_only` | 5.4139 | 33.4606 dB | 0.9827 |

阶段判断：

- scene 12 上，`proposed_v2_j` 明显优于随机采样和旧版 `proposed`。
- `building_only` 表现也较强，说明建筑复杂度是有效采样线索。
- `weak_only` 表现最差，说明只盯着弱覆盖会忽略空间代表性。

## 8. 阶段五：多种子、采样预算和论文汇总

对应提交：

```text
532390f  Add paper experiment batch workflow
```

### 8.1 遇到的问题

单个随机种子或单个采样率的结果不够稳定，无法支撑论文结论。

### 8.2 解决办法

新增批量实验入口：

```text
lanc/run_paper_experiments.py
```

以及汇总入口：

```text
lanc/summarize_paper_results.py
```

支持三类实验：

```text
多种子稳定性实验
不同采样预算实验
一键论文表图汇总
```

多种子设置为：

```text
42 / 2024 / 3407
```

采样预算设置为：

```text
2% initial + 1% per round
5% initial + 2% per round
10% initial + 2% per round
```

每个子实验都写入 `batch_manifest.csv`，记录命令、随机种子、采样率、状态、输出目录和日志。

## 9. 最终实验结果

### 9.1 Scene 13 单次独立验证

不重新调参，直接使用 scene 12 已经固定好的 `proposed_v2_j`。

| 指标 | Zero-shot | 主动微调后 |
| --- | ---: | ---: |
| Encoded RMSE | 5.1604 | 5.0251 |
| PSNR | 33.8771 dB | 34.1078 dB |
| SSIM | 0.9708 | 0.9741 |

主动微调后：

```text
RMSE 降低 2.62%
PSNR 提升 0.2308 dB
SSIM 提升 0.0032
```

这说明主动微调可以改善独立验证场景的覆盖图，即使提升幅度小于 scene 12 的开发集结果。

补充说明：scene 13 单次实验中，`building_only` 的最终 RMSE 更低，为 4.6466。但由于 `building_only` 不是当前论文主线策略，也没有进入最终主线图表，汇报时应将这一点作为补充观察，而不是省略不提。

### 9.2 Scene 13 多种子稳定性

使用 3 个随机种子的均值与标准差：

| 策略 | RMSE 均值 | RMSE 标准差 | PSNR 均值 | SSIM 均值 |
| --- | ---: | ---: | ---: | ---: |
| `random` | 4.9029 | 0.1435 | 34.3242 dB | 0.9757 |
| `proposed_v2_j` | 4.9259 | 0.0965 | 34.2821 dB | 0.9748 |
| `uniform_grid` | 5.0939 | 0.1194 | 33.9914 dB | 0.9759 |
| `proposed` | 5.3632 | 0.1407 | 33.5443 dB | 0.9766 |
| `weak_only` | 5.5559 | 0.0286 | 33.2359 dB | 0.9744 |

结论必须写成：

- `proposed_v2_j` 的平均 RMSE 略微高于 `random`，没有全面超过随机采样。
- `proposed_v2_j` 明显优于 `uniform_grid`、旧版 `proposed` 和 `weak_only`。
- `proposed_v2_j` 的 RMSE 标准差比 `random` 更低，说明结果更稳定。

### 9.3 采样预算结果

| 最终采样比例 | Random RMSE | `proposed_v2_j` RMSE | 结论 |
| ---: | ---: | ---: | --- |
| 7.0% | 5.1560 | 5.3735 | 低预算下随机采样更好 |
| 15.0% | 5.0533 | 5.0251 | 中预算下 `proposed_v2_j` 略优 |
| 20.0% | 4.7816 | 4.7609 | 高预算下 `proposed_v2_j` 略优 |

这说明：

- 采样预算增加后，覆盖误差整体下降。
- `proposed_v2_j` 更适合中高采样预算。
- 低采样预算下，建筑优先策略可能过于集中，反而弱于随机覆盖。

### 9.4 Zero-shot 与主动微调总对比

| 实验 | Zero-shot RMSE | 主动微调 RMSE | 改善 |
| --- | ---: | ---: | ---: |
| Scene 12 开发实验 | 4.9958 | 4.5276 | 9.37% |
| Scene 13 单次验证 | 5.1604 | 5.0251 | 2.62% |
| Scene 13 多种子均值 | 5.1604 | 4.9259 | 4.54% |

最稳定的主线结论是：

> 少量目标场景 UAV 模拟测点可以提升跨场景覆盖预测精度，策略优劣则依赖采样预算和场景分布。

## 12. 下一步建议

### 12.1 最近一步：先做导师汇报

建议下一步不再立刻改模型，而是先把以下材料整理给导师：

汇报时要主动说清楚：

- `proposed_v2_j` 比旧策略和几个普通 baseline 更好。
- `proposed_v2_j` 没有稳定超过随机采样。
- 因此后续要么增加数据场景，要么调整策略评价方式。

### 12.2 第二步：根据导师意见决定是否补数据

如果导师认可“少量测点提升覆盖预测”的主线，可以：

1. 冻结当前 `proposed_v2_j`，不要再根据 scene 13 调参。
2. 新增一个完全独立的数据集或场景，作为最终测试集。
3. 用它回答“模型和采样策略能否跨数据集泛化”。
4. 不把新增测试集用于策略权重搜索。

如果导师认为论文应该突出主动策略优势，则需要：

1. 保留 scene 12 作为策略开发场景。
2. 保留 scene 13 作为独立验证场景。
3. 增加至少一个独立测试场景。
4. 重新审视 `proposed_v2_j` 的低预算表现。
5. 不通过修改 scene 13 结果来制造优势。

### 12.3 第三步：真实无人机数据接入

如果后续能够进行真实 UAV 采集，建议操作流程如下：

1. 在目标区域选择与 FARM 城市场景接近的三维测点。
2. 记录每个测点的经纬度、相对坐标、高度和采样时间。
3. 记录对应基站的频率、方向图、Tx 位置和 yaw。
4. 将实测值统一映射到当前 FARM 编码尺度，或用明确的物理单位重新训练。
5. 使用当前 scene 11 模型作为初始权重。
6. 只使用少量实测点做低学习率微调。
7. 在未采集区域评估，而不是在采集点上评估。
8. 比较零样本、随机选点和 `proposed_v2_j`。

当前代码已经预留了主动采样接口，主要入口是：

```text

```

### 12.4 第四步：再进入路径优化

当前还没有实现 UAV 路径优化。等主动选点闭环稳定后，再单独增加：

- 飞行距离约束。
